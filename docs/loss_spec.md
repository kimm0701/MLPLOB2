# 손실 계산 사양 (이관용)

호가창 주문흐름으로 중간가격 수익률을 다중 horizon 회귀할 때, **정답을 어떻게
만들고 손실을 어떻게 재는지**를 재현 가능한 수준으로 적는다. 모델 구조와는
무관하다 — 입력 [B, 100, 24] 를 받아 [B, 4] 를 내놓는 것이면 무엇이든 된다.

관련 코드: `scripts/make_targets.py`, `preprocessing/ofi_dataset.py`,
`models/regression_engine.py`, `utils/metrics.py`, `ofi_spec.py`

---

## 전체 흐름 한 장

```
원 단위 가격            mid[k+h] − mid[k]            종목마다 가격대가 달라 비교 불가
  │
  │  ÷ tick                                          §1
  ▼
틱 단위                 y_ticks  [K, 4]              "호가 몇 칸" — 종목 간 의미 동일
  │
  │  ÷ (sigma[k] × level)                            §2 §3
  │      sigma = 틱 단위 움직임의 **롤링(인과적 EWMA) 표준편차**, 반감기 300초
  │      level = 종목 상수 (학습일 분산의 중앙값)
  ▼
무차원 z                y  [4]                       "평소 움직임의 몇 배"
  │
  │  clip(clip_lo, clip_hi)   ← 학습에만               §5
  ▼
학습 정답
                        │
                        ├──▶  MSE(pred, y)           §6   손실은 여기서 끝
                        │
                        └──▶  × scale                §7   채점은 되돌린 뒤
                                scale = sigma[k] × level × tick / price[k]
                              ▼
                              소수 수익률  →  R², 피어슨 IC
```

**핵심 두 가지.**

1. **나누는 값은 시점마다 다르다.** `sigma[k]` 는 롤링이라 k 마다 값이 바뀐다.
   종목당 상수 하나가 아니다. 조용한 구간의 2틱과 시끄러운 구간의 2틱이
   서로 다른 z 가 되는 것이 이 설계의 요점이다.
2. **4개 horizon 을 같은 값으로 나눈다.** horizon 별로 따로 표준화하지 않는다
   (§4 에 이유).

## 0. 전제와 기호

| 기호 | 뜻 |
|---|---|
| `K` | 하루치 이벤트(호가창 갱신) 개수 |
| `mid[k]` | k 번째 이벤트 직후의 중간가격 = (최우선매수 + 최우선매도)/2 |
| `ts[k]` | k 번째 이벤트의 시각 (ms) |
| `tick` | 그 종목의 최소 호가 단위 |
| `H` | horizon 목록 `[0.5, 1.0, 1.5, 2.0]` 초 (절대 시간, 종목 공통) |

**시계열은 이벤트 단위다.** 한 칸 = 호가창 갱신 1건이며, 시간 간격은 불규칙하다.
따라서 배열 인덱스로 시간을 계산해서는 안 되고 반드시 `ts` 를 봐야 한다.

디스크 배치:

```
{cache}/{종목}/{날짜}_px.npy   [K, 3]  float64   (mid, bid, ask)
{cache}/{종목}/{날짜}_ts.npy   [K]     int64     버킷 종료 시각 (ms)
{cache}/{종목}/{날짜}_x2.npy   [K, 24] float32   입력 특징
{cache}/{종목}/{날짜}_yt.npy   [K, 4]  float32   정답 (틱 단위, 정규화 전)
{cache}/{종목}/{날짜}_sg.npy   [K]     float32   인과적 sigma (틱 단위)
{cache}/targets.json                             종목별 상수
```

`targets.json` 의 종목별 항목:

```json
{
  "tick": 0.01,
  "level": 0.5814,
  "halflife_sec": 300,
  "horizons_sec": [0.5, 1.0, 1.5, 2.0],
  "winsor_pct": 0.5,
  "clip_lo": [-3.79, -5.09, -6.08, -6.90],
  "clip_hi": [ 3.79,  5.09,  6.11,  6.98],
  "fitted_on": ["20260714", "...", "20260727"]
}
```

`level`, `clip_lo`, `clip_hi` 는 **학습일에서만** 산출한다. 검증일·시험일은
산출에 절대 쓰지 않는다.

## 1. 정답: 틱 단위 미드 변화

```python
def targets_by_seconds(mid, ts_ms, tick, horizons_sec):
    n = mid.size
    y = np.full((n, len(horizons_sec)), np.nan, dtype=np.float32)
    for j, h in enumerate(horizons_sec):
        k = np.searchsorted(ts_ms, ts_ms + h * 1000.0, side="left")
        ok = k < n
        y[ok, j] = (mid[k[ok]] - mid[ok]) / tick
    return y
```

`ts[k] + h*1000` 이상인 **첫 이벤트**를 찾아 그 시점의 미드와 비교한다.
하루 끝을 넘어가면 `NaN` 으로 두고, 학습·평가 양쪽에서 제외한다.

**틱으로 나누는 이유:** 원 단위로 두면 가격대가 다른 종목을 한 모델에 못 넣는다.
틱은 "호가가 몇 칸 움직였나" 라서 종목 간 의미가 같다.

미드에 결측이 있으면 직전 값으로 메우되(`np.maximum.accumulate` 인덱스 방식),
**원래 결측이던 시점의 정답은 NaN 으로 무효 처리**한다. 메운 값으로 정답을
만들면 없는 신호를 있다고 가르치게 된다.

## 2. 인과적 변동성 sigma

같은 −2틱이라도 조용한 장에서는 큰 사건이고 시끄러운 장에서는 잡음이다.
그래서 **그 순간의 변동성**으로 나눈다.

```python
def causal_sigma_sec(mid, ts_ms, tick, base_sec, halflife):
    n = mid.size
    back = np.searchsorted(ts_ms, ts_ms - base_sec * 1000.0, side="left")
    r = np.zeros(n)
    good = back < np.arange(n)
    d = (mid - mid[np.minimum(back, n - 1)]) / tick
    r[good] = np.where(np.isfinite(d[good]), d[good], 0.0)

    alpha = 1.0 - 0.5 ** (1.0 / max(halflife, 1))
    warm = min(halflife, n)
    acc = float(np.mean(r[:warm] ** 2)) or 1.0
    var = np.empty(n)
    for i in range(n):
        acc += alpha * (r[i] * r[i] - acc)     # 갱신 후 기록 = 현재까지만 반영
        var[i] = acc
    return _apply_floor(np.sqrt(np.maximum(var, 1e-12)), halflife)
```

**설계 규칙 네 가지.**

1. **`r[i]` 는 과거를 향한 수익률이다** — `mid[i] - mid[i - base 구간]`. 미래를
   향하게 짜면 정답이 자기 자신의 분모에 들어가 결정계수가 통째로 거짓이 된다.
2. **`base_sec` 은 가장 짧은 horizon(0.5초)과 같다.** 단위를 맞추기 위해서다.
   sigma 는 **하나만** 저장하고 4개 horizon 전부 같은 값으로 나눈다 (§4 참고).
3. **반감기는 초로 정하고 종목별로 이벤트 수로 환산한다.**
   `halflife = max(50, round(halflife_sec * K / 하루_길이_초))`.
   이벤트 개수로 고정하면 종목마다 실제 시간이 달라진다 — 실측으로 1200 이벤트가
   86초/68초/166초였다.
4. **하한(floor)은 워밍업 구간에서만 구한다.**

```python
def _apply_floor(sig, halflife):
    w = min(max(halflife, 100), sig.size)
    floor = float(np.percentile(sig[:w], 5.0)) if w else 0.0
    return np.maximum(sig, max(floor, 1e-6))
```

하루 전체 분포로 하한을 잡으면 그 한 숫자에 미래가 섞인다. 앞쪽 `halflife`
개만 쓰면 실제로 학습에 쓰는 모든 시점에 대해 하한이 과거 정보다.

> **회귀 테스트로 반드시 걸어둘 것:** 배열 뒤쪽 절반을 바꿨을 때 앞쪽 sigma 가
> 변하면 미래 참조다. 이 테스트가 실제로 버그를 잡았다.

`halflife_sec = 300` 은 후보 10/30/60/120/300/900초와 고정 sigma를 교차검증해
고른 값이다 (성적 1.220/1.118/1.069/1.044/1.021/1.007/1.892 — 평평한 구간의
가운데).

## 3. 종목 수준 보정 `level`

sigma 가 시간 변동을 걷어낸 뒤에도 **종목별 수준 차이**가 남는다. 짧은 창의
EWMA 는 실현분산을 과소평가하는데 그 정도가 종목마다 다르기 때문이다
(반감기 1분 실측: AMD 1.11 / META 1.38 / MRVL 1.07).

학습일에서 `y/sigma` 의 분산을 날짜별로 구한 뒤 **중앙값**으로 `level` 을 잡아,
가장 짧은 horizon 의 분산이 정확히 1 이 되게 한다.

> **평균이 아니라 중앙값을 쓴다.** 학습일 분산이 0.03~7.53 까지 퍼져 있어서
> 평균은 이상한 하루에 끌려간다. 중앙값으로 바꿔 종목 간 격차가 2.1배에서
> 1.65배로 줄었다.

## 4. 정규화 — Dataset 이 표본마다 수행

```python
denom = float(sigma[k]) * level
y = y_ticks[k] / denom                      # [4]  무차원
if target_clip is not None:                 # 학습에만
    np.clip(y, clip_lo, clip_hi, out=y)
scale = denom * tick / max(price[k], 1e-9)  # 되돌릴 배율
return x, y, scale
```

**4개 horizon을 같은 값으로 나눈다.** horizon별로 따로 표준화하지 않는다.
그래서 먼 horizon 일수록 정답이 자연히 커진다:

```
정규화 정답 표준편차 (MRVL, 자르기 전)
  0.5초 1.569   1.0초 2.172   1.5초 2.652   2.0초 3.061
```

**이건 의도된 설계다.** 크면 제곱오차도 크므로 모델이 먼 horizon 에 더 신경
쓴다. 여기까지 표준화하면 4개가 균등해지면서 신호가 실제로 있는 짧은 쪽이
묻힌다. horizon 을 2.5·3초까지 늘리지 않고 2초에서 끊은 것도 같은 이유다
(6개로 늘리면 1초 이하 비중이 30.7% → 14.8% 로 떨어진다).

## 5. Winsorize — **학습에만**

상하위 0.5% 를 경계값으로 누른다. 경계는 **z 공간에서 학습일로만** 산출한다.

```python
z = y_ticks / (sigma[:, None] * level)
clip_lo, clip_hi = np.percentile(z[finite], [0.5, 99.5], axis=0)
```

정답의 절반 이상이 0이고 가끔 크게 튄다. 제곱오차는 이 몇 개에 끌려가므로
누른다.

> **검증·시험 정답은 절대 자르지 않는다.** 자른 정답으로 채점하면 문제가
> 쉬워져 성적이 부풀려진다. 코드에서 `winsorize` 플래그는 학습 split 에만
> 넘긴다.
>
> **경계값이 없으면 조용히 넘어가지 말고 `KeyError` 를 던질 것.** 예전에
> `fit_normalizer` 를 다시 안 돌려 경계가 없는 상태로 3 epoch 을 낭비했다.

효과가 크다. 1% 만 잘랐는데 분산의 약 68% 가 사라진다 (MRVL 0.5초 표준편차
1.569 → 0.882). 정답 꼬리가 그만큼 두껍다는 뜻이며, **0.5% 가 최적인지는 아직
검증하지 않았다.**

## 6. 손실

```python
loss = MSE(pred, target)      # [B,4] 대 [B,4], 배치·horizon 전체 평균
```

정규화된 공간에서 잰다. 되돌리지 않는다. `loss_scale` 은 정답 정규화를 켜면
1.0 이다.

**MSE 를 쓰는 이유.** 정답의 절반 이상이 정확히 0 이다(0.5초 동안 미드 불변).
Huber/MAE 계열은 중앙값을 겨냥하는데 여기서는 중앙값이 0 이라 **"항상 0" 이
최적해가 되어 아무것도 배우지 않는다.** MSE 는 평균을 겨냥하므로 0 이 많아도
신호가 남는다.

### 이 숫자를 읽는 법

손실값 자체는 의미가 없다. **"항상 0이라 답하는 모델"과 비교해야** 읽힌다.

```
검증셋 기준           0 이라 답할 때   실제 모델   차이
AMD                     3.7845        3.76228    0.0222
META                    4.0877        4.07394    0.0138
MRVL                    2.7510        2.73732    0.0137
```

`0.0222 / 3.7845 = 0.0059` 가 AMD 의 4개 horizon 평균 결정계수와 일치한다.

**종목 간 손실 비교는 무의미하다.** META 손실이 큰 건 못해서가 아니라 정답이
원래 크기 때문이다. 같은 종목 안에서 epoch 끼리만 비교하라.

## 7. 평가 — 되돌린 뒤 잰다

```python
pred_ret   = pred   * scale      # scale = sigma * level * tick / price
target_ret = target * scale      # 자르지 않았으므로 원본 수익률과 동일
```

`scale` 은 **표본마다 다르므로 배치에 실어 보낸다**. 종목 상수 하나로 되돌리면
틀린다.

측정 지표:

| 지표 | 정의 | 비고 |
|---|---|---|
| `r2` | `1 - SS_res/SS_tot`, horizon 별 | **주 지표** |
| `ic` | **피어슨** 상관 | `R² ≤ IC²` 관계가 성립하는 쪽 |
| `ic_rank` | 스피어만 | 진단용만 |
| `r2_cal` | `pred` 에 최적 상수배를 곱한 뒤의 R² | 크기 오차와 방향 오차를 분리 |

**보고 규칙**

- 결정계수는 **소수점**으로 적는다. `0.00933` 이지 `0.933%` 가 아니다.
- **방향정확도는 보고하지 않는다.** 오해를 부른다 — META 가 방향정확도 54%
  인데 결정계수는 −0.0032 였다. 부호만 맞히는 것과 크기까지 맞히는 것은 다르고,
  마켓메이킹에는 후자가 필요하다.
- 상한을 논할 때 `R² ≤ 피어슨 IC²` 를 쓴다. 스피어만으로 계산하면 상한이
  2.4배 부풀려진다.

`r2_cal` 이 `r2` 보다 크게 높으면 **방향은 맞는데 크기를 과하게 예측**하는
것이다. 범용 모델이 종목을 구분 못 할 때 전형적으로 나타난다 (META 가
−0.00172 → 보정 후 0.00060).

## 8. 손실과 결정계수는 서로 다른 축이다

```
손실        정규화 공간 · 4 horizon 평균 · 먼 horizon 이 지배
결정계수    소수 수익률 공간 · horizon 별 독립
```

그래서 어긋난다. 실측:

```
epoch 2   손실 3.52451 (최고, 체크포인트 저장됨)   통합 0.5초 R² 0.00791
epoch 3   손실 3.52474 (조금 나쁨)                통합 0.5초 R² 0.00807 (최고)
```

**조기종료를 손실로 걸면 짧은 horizon 최적점을 놓친다.** 마켓메이킹처럼 짧은
쪽이 중요한 용도라면 조기종료 기준을 `0.5초 R²` 로 바꾸는 편이 맞다.

## 9. 재현 체크리스트

- [ ] `level`·`clip_lo`·`clip_hi` 를 **학습일에서만** 산출했는가
- [ ] sigma 가 과거만 보는가 (뒤쪽 절반을 바꿔 앞쪽이 안 변하는지 테스트)
- [ ] sigma 하한을 워밍업 구간에서만 구했는가
- [ ] 반감기를 **초** 로 정하고 종목별 이벤트 수로 환산했는가
- [ ] winsorize 가 학습 split 에만 걸리는가
- [ ] 경계값이 없을 때 조용히 넘어가지 않고 예외를 던지는가
- [ ] 되돌릴 `scale` 을 표본마다 배치에 실어 보내는가
- [ ] `NaN` 정답 표본을 학습·평가 양쪽에서 제외했는가
- [ ] 결정계수를 **되돌린 뒤 자르지 않은 정답**으로 계산하는가
- [ ] IC 가 피어슨인가
